# reserve8: raw RGB / native land-cover qualification

No model, inference, baseline outcome, or test prediction is required. Run the geographic and decoding steps on Featurize. Paths below are relative to the project or cloud stage root. The frozen reserve8 CSV SHA is checked by the geometry code. Run on the existing instance, with 30 GB free **local scratch** and the mounted or previously verified native 2017 reference and 2019 TIGER geometry. Do not substitute a web screenshot or reference-map colorization for acquired imagery.

1. From the repository: run `.venv/bin/python experiments/g6h/audit.py`. Stage `experiments/g6h`, `manifests/g6g/{reserve8_roster.csv,nyc_service_metadata.json}`, `manifests/g6h/sources/index.zip` (as `index.zip`), and `manifests/g6h/baseline_coverage.csv` (as `baseline_coverage.csv`) in a persistent cloud work directory. The service index is not the raw orthophoto index.
2. For reproduction, stage the supplied archive_sources.json as `archive_sources.pinned.json`; the downloader rejects a changed published revision. Cloud: `python experiments/g6h/source_index.py`. `python experiments/g6h/acquire.py` downloads the five official public archive versions, checks byte ranges, and resumes completed ranges. Pin/archive the returned manifest and compare its ETags with the supplied receipt before accepting a reproduction. `python experiments/g6h/catalog.py` reconciles the official index to the ZIP directories, including tiles filed in another borough.
3. Cloud: `python experiments/g6h/qualify.py masks && python experiments/g6h/qualify.py tracts`. JP2s are CRC checked, hashed, decoded, checked against index bounds and summarized as bit-packed masks. The final step checks every tract against its frozen reference counts. Keep `qualification/`, the logs, source locations, and the raw archive receipts. `channel_check.py` provides an auxiliary comparison with the published city display; it does not select bands, thresholds or tract membership. `early_validate.py` is optional; do not run concurrently with the final tract pass. Acquiring, indexing and decoding are CPU/network workloads. Set a new directory for a fresh run or retain the same scratch AND stage for a resume.
4. Independently enumerate the actual addressing envelope of the fixed 512-pixel loader: `python experiments/g6h/footprints.py ~/work/jev-g6a/tl_2019_36_tract.zip ~/g6a-native/NYC_2017_LiDAR_LandCover.img footprints-v1` (new output directory). These 2016 display-pyramid tile keys are not the borough JP2 filenames. Save footprint.json; the SQLite manifest is retained on Featurize. No data or model is read from any prior evaluation output.
5. Copy the cloud receipts (small JSON files, not imagery) into `manifests/g6h/qualification/`, and `index_links.csv` to `manifests/g6h/`. Run `.venv/bin/python experiments/g6h/summarize.py`. If any file or reference check is missing this fails, rather than issuing a partial qualification. Frozen assignments and checksums are immutable; applicable eligibility and observed analysis support are separate fields.

Raster rule: use the official index's six-inch State Plane grid and embedded bounds. Source has four bands; the first three supply visible imagery. The fourth is not an alpha mask. Validity requires three decodable bands, valid GDAL masks when provided, and not all black or all white. For alignment from source centers to reference centers all four bilinear neighbors must be valid within the same source tile; the conservative seam guard can undercount coverage slightly. No label values are interpolated. Pixel centers inside the TIGER geometry define the polygon; reference 1–8 is mapped and 4 is water. Each cell is 0.25 square feet. These are technical coverage masks, not a guarantee of acquisition-date concordance, positional accuracy or semantic ground truth.

6. On Featurize run `python experiments/g6h/receipts.py` after all tracts and the footprint enumeration finish. Copy execution_receipt.json and footprints-v1/footprint.json to manifests/g6h. Local release: `.venv/bin/python experiments/g6h/frozen_sensitivity.py`, then `.venv/bin/python experiments/g6h/report.py` and `.venv/bin/python experiments/g6h/test_qualification.py`. Check archive digests against execution_receipt.json. The original-weight sensitivity never modifies the frozen roster or original weighting file.

The repository ships all 1,154 cloud receipts in `manifests/g6h/run/qualification.jsonl.gz`. For an offline replay without a cloud connection, run `.venv/bin/python experiments/g6h/package_receipts.py unpack` before steps 5–6. The compressed window SQLite DB and the exact cloud code snapshot are in the same run directory. Source imagery stays on the instance; do not place the 21.5 GB of archives in Git.

For a full offline replay on the released files, use `bash experiments/g6h/replay.sh` from the project root. Local analysis versions are pinned in `manifests/g6h/run/analysis_environment.json`; cloud raster versions are in `execution_receipt.json`. The frozen 2017 raster source checksum and native member CRCs are in `manifests/g6/source_fingerprints.json`. A fresh machine needs the ~97.74 GB native .ige data file in addition to this stage's scratch requirement.
